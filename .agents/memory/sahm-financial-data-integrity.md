---
name: SAHM financial data integrity
description: User's standing constraint for financial values and analysis displayed in SAHM.
---

SAHM is for students and beginner investors in Kuwait reading listed-company financial reports. Keep explanations educational, not investment advice, and interpret signals with sector context, especially for banks.

Only show financial analysis derived from actual source-backed report extraction. Preserve the reported value and expose its reporting period, currency, unit scale, verification status, and source reference when available. Compare periods only for the same verified metric and label with matching currency and unit scale plus source evidence; if that evidence is absent, state that the trend cannot be determined. Any percentage change must be calculated deterministically from parseable reported amounts, never guessed. Keep percentages in the structured comparison; AI explanations may describe direction in words but must not introduce percentages. Keep source references separate from plain-language meanings and investor interpretation; do not repeat the filename, page, reporting year, or extracted amount in the interpretation.

Only extract figures from rows on an identified financial statement page, aligned to the current reporting-period column. Narrative mentions elsewhere in the report are not metric evidence; without a reliable row, period, currency, unit, and page, show the metric as not verified. Keep income-statement periods (“for the year ended”) distinct from balance-sheet dates (“as at”).

**Why:** The user repeatedly asked that SAHM not invent figures or present demonstration data as financial results; broad searches previously promoted narrative percentages and blurred period-flow values with point-in-time balances. The explanation model also produced unsupported percentage claims when comparisons were available.

**How to apply:** Before changing report, dashboard, or explanation screens, distinguish visual design examples from actual API data and reuse saved-report fields and citations. Require a statement heading and current-year-column alignment for extracted figures; if comparable verified periods are missing, explain the limitation rather than filling it in. Calculate percentage changes in deterministic code, have AI explain direction only, and keep percentage-claim validation strict. Treat rising liabilities as a watch item requiring sector context, not an automatic risk label.

When correcting a saved report, update only the exact user-selected record; do not automatically refresh duplicates. Clear or regenerate any explanation bundle that describes changed figures so stale AI text cannot contradict the corrected extraction.

**Why:** The user approved correcting only the most recent Zain report and separately approved clearing its outdated explanation bundle; an older duplicate was intentionally left unchanged.

**How to apply:** Verify the selected record’s identity and expected old values before writing, constrain the update to that record, invalidate explanations tied to changed metrics, and read back other matching records to confirm they were untouched.

For banks, do not explain a “net operating income” statement row as ordinary sales revenue or assume its component breakdown from the label alone.

**Why:** Generic AI definitions can mischaracterize bank operating-income rows as sales after returns and discounts, which is not supported by the extracted statement line.

**How to apply:** When a verified source row is identified as net operating income, describe it as income generated by banking operations, distinguish it from net profit, and cite the row without inventing its components.
